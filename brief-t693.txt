Background (T688 root cause, driver-verified):
- The T686 Image (clang 21.0.0 / LLD 21.0.0) placed its cold functions
  inside the freeable init range [__init_begin 0xffffff8009170000,
  __init_end 0xffffff8009270000). free_initmem() passes that range with
  poison w2=0 to free_reserved_area(), which memsets every page; the
  `bl printk` at free_reserved_area+420 (0xffffff80081ec4b8) then
  executes `udf #0x0` at printk+0. The undefined-instruction exception
  enters die(), takes die_lock (0xffffff80093b514c, value 0x101), calls
  __die() — also zeroed — faults again, and the second die() spins
  forever on the same die_lock. Only CPU0 is online, so this is a
  re-entrant self-deadlock.
- Compiler-side cause: Linux 4.19 TEXT_TEXT matches `.text.unlikely`
  exactly; clang 12+ emits `.text.unlikely.` with a trailing dot, so
  LLD orphan-places the section into the init range. The canonical
  kernel (clang 11.0.1) places printk 0xffffff8008216980 below _etext
  and boots to userspace in the A/B control.
- Route A (T689, already built) restores the canonical LTO trio
  (CONFIG_LTO=y, CONFIG_THINLTO=y, CONFIG_LTO_CLANG=y) in the hope the
  LTO layout moves the cold functions back below _etext. Full hardening
  parity was NOT applied (CFI/SHADOW_CALL_STACK still unset) — record
  that, do not change it in this lane. The driver-run gate above shows
  the layout DID move back below _etext. This lane proves the flight.

## Standing evidentiary rules

- TEN-PASSES: reproducibility = 10 consecutive passes before any "reproducible" claim.
- GUEST-MARKER-ONLY: boot markers count only when printed by the guest process, never the harness.
- NO-MISSING-INPUTS: missing inputs = hard gate, not a guess.
- GUEST-CONSUMES-ARTIFACT: injection tracks must prove the guest actually consumes the artifact.
- QEMU-REGRESSION-VECTORS: decoder/emulator work needs QEMU-matched regression vectors per class.
- INITRAMFS-DECISION: the T679 vendor.img CPIO-member install route is executed in this lane if a vendor-side fix is built.
- DEATH-NOTE: every lane ends with findings or a death certificate — no unclosed lanes.
- FINDINGS-OR-AUTO-FAIL: no verdict is accepted without its findings file on disk.
- RECONSTRUCTED-TAG: a findings file reconstructed by the reviewer must carry an explicit "reconstructed by reviewer" tag with date.
- WALL-TYPE-TAG: every wall is tagged guest / WASM / engine; only type-1 (guest) walls are shared with Rust, and every type-1 fix records "Rust par bhi lagu: haan/nahi".
- DISPLAY-SCAFFOLD: display lanes prove frame commit by guest-origin evidence only; snapshot byte differences are never frame-commit proof.
