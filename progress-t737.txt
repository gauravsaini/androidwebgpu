### Defect 2 RESOLVED — LD_LIBRARY_PATH mechanism found (box debugfs, fresh)

- The flown system image `af40403a` is a GSI system-as-root image: its root has a `system/` directory holding the real partition content; `bin` is a symlink (11 B → `system/bin`); there is NO `lib64` at the image root.
- The image's libEGL.so is at `<image-root>/system/lib64/libEGL.so` (debugfs stat: regular file, 290,120 B; dumped, SHA `fed36a9b`). `/lib64/libEGL.so` does NOT exist in the image (debugfs: "File not found by ext2_lookup").
- Mounted at /sysimg, the image's libEGL is at `/sysimg/system/lib64/libEGL.so` — NOT `/sysimg/lib64/libEGL.so`. The T736 script set `LD_LIBRARY_PATH=/sysimg/lib64`, a directory that does not exist in the mounted image, so the linker found nothing there and fell back to the default `/system/lib64` — the ramdisk's libEGL (`a9641828`). That is the whole mechanism. No linker-config involvement: the T736 CPIO's `linkerconfig` entry is an EMPTY directory (no ld.config.txt), consistent with the UART's "failed to find generated linker configuration" warnings.
- libEGL byte-identity (brief requirement): `eglDupNativeFenceFDANDROID` at 0x297a8, 56 bytes — IDENTICAL between image (`fed36a9b`) and ramdisk (`a9641828`) files (cmp clean). `eglGetProcAddress` at 0x28b5c, 96 bytes — 3 bytes differ, confirmed by disassembly to be exactly two data-address operands shifted by 0x10 (the 16-byte file-size difference): `adr x8, 54c58` vs `54c48`, `add x0, #0xf12` vs `#0xd48`. Logic-identical, as the T736 findings claimed.
- T737 fix: `LD_LIBRARY_PATH=/sysimg/system/lib64:/sysimg/lib64`, set via `export` AND the exec prefix. The flight-12 SP2 maps line is the proof (expect `/sysimg/system/lib64/libEGL.so`).

### Mount justifications (T736 reflection lesson — binding)

Every mount in the T737 early-ramdisk script, with its guest consumer + whether first-stage init re-mounts the same point:
- `/sysimg` (vda, ro): consumer = the probe (needs the image's libEGL.so + deps). Init does NOT mount /sysimg — safe. (T736-proven: rc=0, tripwire passed.)
- `/vendor` (loop1, ro): consumer = the probe (needs the driver .so). Init mounts /vendor itself in first stage — but the T734 flights 8/9 and the T736 flight both ran with this pre-mount and init booted past it (T736's abort was proc-only, L435). Proven safe by flight evidence; kept.
- `debugfs` on /sys/kernel/debug: consumer = the probe (needs the sw_sync timeline path). Init does NOT mount debugfs in first stage. Proven safe by T734 flights 8/9 + T736 flight (no debugfs complaint in the UART). Kept.
- `/proc` (proc): consumer = the probe's maps_lookup ONLY (SP2's maps line proving which libEGL loaded). Init mounts /proc itself in first stage with hidepid=2 and treats an existing mount as fatal (INIT-PROC-MOUNT-CONFLICT, T736 L435). MUST be scoped: mount → probe → UNMOUNT before the handoff to /init. The T737 script does exactly that, with rc hooks for the mount, the probe, and the unmount.
- `/data` (T666 ext4/tmpfs) + `/data/media` (T667 tmpfs): consumers = init's later stages + services (gatekeeper, fingerprint, settings DBs). Long-standing since T666/T667; T734 flights 8/9 booted cleanly with them. Init does not re-mount /data in first stage. Kept unchanged.
